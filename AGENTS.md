## 🏗️ Architecture Overview

LemonWeb is a **recipe publishing platform** with a two-subdomain architecture:

```
┌─────────────────────────────────────────────────────────────┐
│                   lemonnutrition.eu                         │
│                   (Landing Page)                            │
│                GitHub Pages                                 │
└─────────────────────────────────────────────────────────────┘
           ↓
    ┌──────────────┬────────────────┐
    │              │                │
┌───▼───┐      ┌───▼──────┐        │
│ app.  │      │ recipes. │        │
│ FE    │      │ API      │        │
└───────┘      └──────────┘        │
 Astro/React    Vercel Functions   │
 (Published)    (Published)        │
```

### **1. Frontend: `app.lemonnutrition.eu`**
- **Framework:** Astro + React
- **Deployment:** Vercel
- **What it does:**
  - Public recipe browsing & sharing UI
  - Recipe import from JSON
  - Hero image display
  - Universal Links handling for iOS deeplinks

### **2. Backend API: `recipes.lemonnutrition.eu`**
- **Framework:** Vercel Functions (serverless)
- **Storage:** Vercel Blob (S3-compatible)
- **What it does:**
  - Recipe publish endpoints (`POST /api/recipes`)
  - Recipe unpublish endpoints (`DELETE /api/recipes/{id}`)
  - Image upload endpoints (`POST /api/images`)
  - Recipe index management (`_index.json`)

### **3. Blob Storage: Vercel Blob**
- **Purpose:** Canonical store for published recipes and hero images
- **Structure:**
  ```
  recipes/
    ├── _index.json          (list of all published recipes)
    ├── {id}.json            (individual recipe)
    └── {id}/
        └── hero.{ext}       (recipe hero image)
  ```

## 🔐 Environment Variables (Vercel)

Set these in **Vercel Settings → Environment Variables** for production:

```
PUBLIC_RECIPE_SITE_URL=https://recipes.lemonnutrition.eu
PUBLISH_API_KEY=<bearer token - shared secret for CookBook + FE>
BLOB_READ_WRITE_TOKEN=<auto-generated by Vercel Blob>
```

**Where they're used:**
- `PUBLIC_RECIPE_SITE_URL`: Frontend config at `src/infrastructure/composition-root.ts`
- `PUBLISH_API_KEY`: Auth header bearer token at `src/infrastructure/auth.ts`
- `BLOB_READ_WRITE_TOKEN`: @vercel/blob library (automatic)

## 🔗 API Endpoints

All requests must include the Bearer token:
```
Authorization: Bearer <PUBLISH_API_KEY>
```

### **POST /api/recipes** - Publish Recipe
```bash
curl -X POST https://recipes.lemonnutrition.eu/api/recipes \
  -H "Authorization: Bearer $PUBLISH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "recipe-uuid",
    "title": "Chocolate Cake",
    "description": "...",
    "imageUrl": "https://recipes.lemonnutrition.eu/recipes/{id}/hero.jpg"
  }'
```

### **DELETE /api/recipes/{id}** - Unpublish Recipe
```bash
curl -X DELETE https://recipes.lemonnutrition.eu/api/recipes/recipe-uuid \
  -H "Authorization: Bearer $PUBLISH_API_KEY"
```

### **POST /api/images** - Upload Hero Image
```bash
curl -X POST "https://recipes.lemonnutrition.eu/api/images?recipeId=recipe-uuid" \
  -H "Authorization: Bearer $PUBLISH_API_KEY" \
  -F "image=@hero.jpg"
```

## 💡 Backend Development Learning Path

If you're learning backend here, focus on **these files in this order:**

### **Phase 1: Understanding the Domain**
1. Read `src/domain/ports.ts` - what storage interfaces do we need?
2. Read `specs/publish-recipe.feature` - what should the happy path be?

4. Read `src/pages/api/recipes.ts` - how do requests flow?
5. Read `src/infrastructure/auth.ts` - how is security enforced?

### **Phase 3: Writing New Features**
7. Write an endpoint test in `tests/api/`
8. Implement the endpoint in `src/pages/api/`
9. Test against local Blob (or mock storage)

### **Phase 4: Deployment & Monitoring**
10. Deploy to Vercel and test against `recipes.lemonnutrition.eu`
11. Check runbook.md for operational concerns

## 🤔 Q&A for Backend Learning

**Q: Why two subdomains (app. + recipes.)?**
- Separation of concerns: frontend is public & cacheable, API is stateless & requires auth
- Easy to scale independently (FE on Vercel Edge, API on Vercel Functions)
- Better security: API token never exposed to browser origins

**Q: What's the flow from CookBook iOS to LemonWeb?**
- CookBook publishes recipe → POST to `recipes.lemonnutrition.eu/api/recipes` + bearer token
- LemonWeb stores in Blob → updates `recipes/_index.json`
- User shares universal link → iOS opens recipe in browser or CookBook app

**Q: Why Vercel Blob instead of a traditional database?**
- Recipes are immutable documents (JSON files)
- Images are static blobs
- Vercel Blob is S3-compatible, simple, and auto-scales
- No DB maintenance overhead

**Q: How do I test locally before deploying?**
- Run `npm test` for unit tests
- Use `npm run dev` to run Astro dev server (FE works locally)
- Mock Blob in tests with in-memory store (see `tests/`)
- Deploy to Vercel staging if you need to test against real Blob
